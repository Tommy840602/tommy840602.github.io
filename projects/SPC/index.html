Highlights

System Positioning

SPC 位於 Plant Simulator → Virtual PLC → DCS → SPC 資料鏈後端，只負責資料接收、合理子組、管制圖、異常告警、人員處置、Camunda 簽核與稽核，不直接控制 PLC，也不回寫 DCS。

Control Chart Modeling

依品質特性選擇統計模型：直徑偏差 diam_error 與 BODY 生長率 gr_rate 使用 X̄-R；晶身長度 body_length 與 BODY 時長 body_duration 使用 I-MR。

Process-aware Subgrouping

直徑與生長率的合理子組採 BODY 10%、30%、50%、70%、90% 五個位置取樣，而不是任意連續切五筆資料，避免長晶連續訊號污染基準。

SPC Diagnostics

支援 Nelson 八項判異規則、X̄／R 越界、異常嚴重度、處置狀態、AR(1) 殘差診斷、管制界線不確定性、Hotelling T² 多變量監控與不同爐台分層分析。

Process Capability

整合 Cp、Cpk、Pp、Ppk、Box-Cox 轉換、常態性檢定、自相關揭露與能力指標有效性說明，並清楚區分規格界線 USL／LSL 與管制界線 UCL／LCL。

Realtime Data Contract

即時資料契約為 cz.dcs.spc.telemetry.v3，以 cycleId、ingotId 識別週期，使用 sourceId + sequence 去重，只在 RUNNING + BODY + IN_PROGRESS 時累積資料。

History vs Realtime

歷史模式從 PostgreSQL／Parquet 以 2×、5×、10× 重播並逐子組播放；即時模式由 DCS ingest、quality gate、cycle buffer、completed subgroup、Redis 與 SSE 組成，斷線重連不偷切歷史資料。

Camunda Governance

規格變更透過 Engineer 提案、部門 Lead 審查、QA Lead 終核後才生效；提案、初審與終核角色不可互相兼任，稽核紀錄採 append-only hash-chain。

Production Readiness

部署包含 Docker Compose、nginx、GitHub Actions、Hetzner shared host、Prometheus metrics、health/readiness probe、production smoke test、Playwright E2E 與 Camunda integration test。

Engineering Focus

這個 repository 最有價值的地方不是單一演算法，而是把製程語意、統計有效性、品質治理與生產環境部署整合成一套完整平台。

製程語意上，合理子組依 BODY 百分比建立，而不是只對時間序列任意分組；Phase I 基準建立與 Phase II 後續監控也有清楚的 frozen baseline 概念。

系統設計上，統計異常會延伸到處置、規格變更、雙關簽核與 audit，Camunda／Zeebe 作為流程狀態權威來源，PostgreSQL 保存規格版本、outbox、事件處置與 audit。

工程實作上，Vue 3 + ECharts 透過 REST API 與 SSE 連接 FastAPI，後端整合 SPC statistics、DCS ingest、Auth/RBAC、Workflow/alarm、Report、health 與 metrics。資料層包含 PostgreSQL 17、Redis 7、Camunda 8.8 與 worker。

維運上，PostgreSQL、Redis、Camunda 與 API 僅暴露於內網或 loopback，外部主要經 nginx 進入，並透過 livez、readyz、health 與 Prometheus metrics 分層檢查服務狀態。
