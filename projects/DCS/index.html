分散式控制系統（Web-Based DCS）

CZ DCS 是一套以 Czochralski 單晶爐為情境的分散式控制系統模擬與工程治理平台，位於 Virtual PLC 與 SPC 之間，負責分散式 PID、操作監控、告警、工程命令、控制腳本審核與製程資料向 SPC 的標準化交付。

Highlights

System Positioning

DCS 位於 Plant Simulator → CZ Virtual PLC → CZ DCS → CZ SPC 鏈路中，不取代 PLC 的聯鎖與順序控制，也不負責 SPC 的統計判異；SPC 同樣不反向寫入控制命令。

Distributed PID Execution

六組控制迴路 DIC、TIC、FIC、PIC、ZIC、SIC 各自配置 Primary 與 Hot-Standby，形成 12 個獨立 Java JVM 控制節點，每個節點保存 PID state、scan counter、input quality、safe output、alarm、tuning limit 與 lease。

Control vs Supervisory Plane

PID 以 100 ms local scan 在控制節點內執行；Gateway 僅負責身份驗證、授權、命令路由、Alarm aggregation、OPC UA、WebSocket 與工程工作流，避免瀏覽器或 WebSocket 進入硬即時控制路徑。

Active Lease and Failover

Primary／Standby 透過 MQTT retained lease 決定 Active Controller，避免兩個副本同時輸出；Primary 故障後 Standby 可接管，具備簡化 leader lease 與 fencing 的 split-brain 防護概念。

Industrial Messaging

內部使用 MQTT、Sparkplug B、Protobuf binary payload、QoS 1、NBIRTH/NDEATH、DBIRTH/DDEATH、Metric alias、bdSeq 與 8-bit sequence number；Gateway 遇到缺少有效 Birth Certificate 的資料會要求 Node Rebirth。

PLC-DCS-SPC Contracts

系統定義 cz.plc.dcs.telemetry.v2 與 cz.dcs.spc.telemetry.v3 兩個版本化邊界契約，DCS 以 1 秒頻率交付 cycleId、ingot、state、phase、outcome、diameterTarget 與 canonical quality tags 給 SPC。

PID Observability

Gateway 每秒透過 WebSocket 發送 dcs.pid.telemetry.v1，前端呈現 SP、PV、Error、Output、Controller identity、scan counter、input quality、P/I/D term、integral state、saturation 與 anti-windup state。

Engineering Governance

控制腳本具備 Lexer、Parser、AST、行/欄錯誤診斷、Sandbox 模擬、watch symbols、tag write inspection、diff、review、approval、version history 與 rollback，並以 server-side session 判斷審核身份。

Network and Deployment Isolation

正式部署採 Hetzner shared host 與 immutable release，健康檢查失敗自動 rollback；對外只暴露 HTTPS，MQTT、OPC UA、資料庫與控制節點不直接暴露到 Internet。

Engineering Focus

這個專案最值得在面試中強調的是控制閉環與 Web 監督層的責任切分：真正的 100 ms PID 執行在獨立控制節點，WebSocket 只負責 supervisory presentation，Gateway 或前端短暫失效時不會使控制掃描停止。

架構亮點在於 PID 不是集中在 Gateway 內建立 12 個物件，而是拆成 12 個獨立 JVM 控制執行單元，搭配 Primary/Hot-Standby、retained lease、safe output 與 input quality，呈現接近真實 DCS 的高可用與 split-brain 防護思維。

資料邊界上，PLC、DCS、SPC 之間使用明確且版本化的 telemetry contract，控制資料不只是一直丟數值，而是帶有 cycle、phase、outcome 與 quality tag 的製程週期語意，利於 SPC、追溯與資料品質治理。

工程治理上，平台不只做操作畫面，也包含 RBAC、SoD、控制腳本 Lexer/Parser/AST、Sandbox、審核流程、版本紀錄、rollback、append-only audit 與 transactional workflow update。

部署上，控制面與監督面分隔為 cz-dcs-control、cz-dcs-supervisory 與 cz-industrial network，只有 Gateway 同時跨網，PLC snapshot 走內部 Docker network，不經公開 reverse proxy。

此平台是工程展示與控制系統模擬，並非經認證的 DCS、PLC 或 SIS；預設禁止實體輸出，不能直接用於真實設備控制。
